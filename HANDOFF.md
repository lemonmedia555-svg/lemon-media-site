## Главные правила работы

1. **Тексты, кнопки и состав блоков — из прототипа `index.html`, дословно.** Меняем только оформление: композицию, цвет, типографику, движение. Новые сущности не выдумывать: демонстрации у компании нет, тарифных карточек нет — только калькулятор.
2. **Дизайн-система — канон.** `design-system/DESIGN.md` + `tokens.css`. Цвета только токенами. Подчёркиваний-маркеров под текстом в системе нет.
3. **Всё фиксировать в git и пушить** на GitHub после каждой законченной правки.
4. **Проверять визуально своими глазами** — скриншоты каждой изменённой секции, а не «должно работать».

## Что утверждено Иваном по первому экрану

- Раскол экрана на две холодные светлые зоны: слева `cool/050 #F4F6FA` (текст), справа `lavender/100 #E4EAF7` (витрина работ). Меню-капсула плавает поверх.
- Справа живая лента: колонки едут в разные стороны, пауза при наведении, 33 уникальные работы из 25 кейсов. Число колонок зависит от ширины: 5 от 1500px, 4 на средних, 3 на мобиле — чем шире экран, тем мельче карточка.
- Форматы визуально различаются: пост, карусель (стопка + счётчик слайдов), сторис (9:16 + полоски прогресса).
- **Карусели и сторис листаются внутри карточки** — стрелки на hover. Отдельное окно просмотра запрещено.
- Жёлтый — только в акцентах: кнопка, галочки, бейджи.
- Ленту («работы») Иван просил не трогать — устраивает.

Тексты прототипа при этом не тронуты — менялось только оформление.

## Ловушки, на которые уже наступали

1. **Специфичность CSS.** Сброс `margin: 0` по тегам (`.dz p`, `.hf p`) перебивает отступы у классов — интервалы молча игнорируются, текст «слипается». Лечится `:where(...)`. При жалобе на композицию сначала мерить фактические зазоры через `getBoundingClientRect`, а не крутить значения вслепую.
2. **Порядок подключения стилей**: `page.css` → потом `hero-final.css`, иначе страница гасит hero.
3. **Кеш CSS у python http.server**: обычный `python3 -m http.server` отдаёт старые стили. Проще поднимать сервер, который сам гасит кеш (Cache-Control: no-store, без Last-Modified), чем дописывать `?v=` к каждому href.
4. **Копий дизайн-системы три** (`assets/design/`, `design-system/` в репозитории, `Бренд/design-system/`) — правя одну, синхронизировать остальные. В `design-system/` кладём только системные файлы: `hero-final.css` и `page.css` — стили страницы, им там не место.
5. `innerText` возвращает текст после `text-transform` — проверка на «Шаг 1 · выберите объём» ложно падает, потому что отрисовано в uppercase.

